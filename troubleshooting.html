서비스를 운영하며 실제로 마주친 오류와 인프라 문제를 진단하고 해결한 기록입니다.

Case A

Postgres 드라이버 호환성 오류

문제

pgbouncer=true 쿼리 파라미터가 psycopg v3와 충돌하며 sqlalchemy.exc.ProgrammingError가 발생했습니다. PgBouncer 트랜잭션 모드는 prepared statement를 지원하지 않는데, psycopg v3가 이를 자동으로 사용하면서 충돌한 것이 원인이었습니다.

해결

해당 파라미터를 제거하고 postgresql+psycopg:// 드라이버로 전환, connect_args={"prepare_threshold": None}를 적용해 문제를 해결했습니다.

Case B

운영 중 발견된 6가지 버그 일괄 해결

발견된 이슈
  • 파티 종료 API 오류
  • 관리자 권한 대소문자 불일치
  • 누락된 모델 컬럼 · API 라우트
  • 탈퇴 기능 미완성 호출
  • 마이페이지 dynamic import 충돌
  • 챗봇 성능 저하 (LIMIT 200 적용)
결과

한 세션에서 6가지 이슈를 순차적으로 진단하고 수정하며 서비스 전반의 안정성을 확보했습니다. 증상 하나에 매몰되지 않고 전체 흐름을 점검하는 방식으로 접근했습니다.

Case C

인프라 마이그레이션 — Render → Oracle Cloud VPS

문제

Render 무료 티어의 배포 할당량이 소진되며 서비스 확장에 제약이 생겼습니다.

해결

Docker Compose로 백엔드와 DB를 컨테이너화해 Oracle Cloud VPS에 배포하고, Caddy 리버스 프록시와 iptables 방화벽 설정으로 Vercel 프론트엔드와의 HTTPS(mixed-content) 통신 문제까지 해결했습니다.

Case D

자동 발행 시 인용구 다음 문단이 사라지는 문제

문제 · 원인

네이버 에디터에 글을 자동 입력하면 인용구 바로 다음 문단만 에러 없이 통째로 사라졌습니다. 실측해 보니 .se-component는 화면 전체 폭이고 실제 글 칸은 그 안의 .se-component-content였습니다. 컴포넌트 기준 좌표로 클릭하면 글 칸 바깥 여백이 눌려 캐럿이 숨은 span.se-blind로 가고, 입력이 허공으로 사라지고 있었습니다.

해결 · 배운 점

클릭 좌표를 .se-component-content 기준으로 바꾸고, 캐럿 위치를 읽어 새 문단이 생겼는지 확인한 뒤 입력하도록 했습니다. 로컬 테스트 환경은 폭이 좁아 이 결함을 잡지 못했기 때문에, 실제 에디터에 연습 글을 넣고 스크린샷으로 확인하는 단계를 검증 절차에 추가했습니다.

Case E

AI가 "성공"이라고 답한 빈 결과 걸러내기

문제 · 원인

사진 판정 결과가 {"shape":"","color":""}처럼 비어 있는데도 정상 응답으로 처리됐습니다. 원인은 사진 경로의 띄어쓰기와 큰 이미지 크기였습니다. 첨부에 실패한 AI가 형식만 맞춘 빈 답을 내고 있었습니다. 카드뉴스 숫자에서도 AI가 틀린 변환 방향(× / ÷)을 쓰는 경우가 있었습니다.

해결 · 배운 점

사진은 띄어쓰기 없는 임시 폴더로 복사해 넘기고, 답에 "읽지 못함" 류 문장이 있으면 실패로 처리했습니다. 숫자는 BigInt 분수 계산기로 식 · 단위 · 변환 흐름을 직접 검산하고, 틀린 줄은 AI에게 다시 고치게 한 뒤 그래도 틀리면 뺐습니다. "형식이 맞다"와 "내용이 맞다"는 다르다는 것을 배웠습니다.
